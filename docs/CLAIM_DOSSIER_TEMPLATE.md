# Claim Dossier Template (draft v0.1)

A dossier puts every argument, every piece of evidence and every source for one claim in one place, challenges each argument by the same criteria, and reports what survives. It follows PRINCIPLES.md.

## 0. Claim
- ID and date:
- Claim, stated precisely (one measurable claim per dossier; split blended claims):
- Scope (population, dose, outcome):
- Reviewer(s) and their own ties:

## 1. Search protocol
- Where searched, search terms, date, and what was included or excluded and why.
- Known limits of the search (for example: snippets only, primary papers not read, no systematic database search).

## 2. Source register
For each source: ID | type (primary trial / cohort / review / mechanistic / commentary / news) | authors | funder and ties | design | population | outcome | standing (retracted, corrected, disputed) | verified [V] or unverified [?].
Primary data and secondary summaries are listed separately. Never let a secondary summary stand in for the primary source without saying so.

## 3. Argument ledger
For each argument: ID | side (supports / opposes / qualifies) | statement | source IDs.

## 4. Challenge (same questions for every argument, either side)
1. Directness: does the evidence measure what the claim says (same population, dose and outcome)?
2. Quality: bias risks, size, duration, confounding.
3. Conflicts: funder and author ties; "not disclosed" is never scored as "none".
4. Standing: replicated, disputed, corrected or retracted?
5. Relevance log: anything set aside gets a written reason.
Result per argument: holds / weakened / not supported / holds only for a narrower claim.
Record this section BEFORE writing the outcome.

## 5. Outcome
- Status: converging / contested / unresolved / unsupported.
- What the evidence shows.
- What it does not show.
- What would change this status.
- Concern by context (outcome, intake level, population) instead of one verdict.

## 6. Change log
Date, change, reason.
